
/* ============================================================================
   ART-NET — THE DESK DRIVES THE PALACE            RULINGS EL, EM, EN, EU, EV

   A lighting console (QLC+, or any desk — Art-Net is Art-Net) sends DMX over
   UDP; `tools/artnet-relay.js` turns it into WebSocket frames; this part is
   the game's end of that wire.  The game becomes an Art-Net visualiser for
   the Palace rig, and its own board steps aside while the desk is talking.

   THIS PART IS THE TRANSPORT AND THE HOLD (RULINGS EM's state and EU).  What
   the bytes MEAN lands in the rulings after it — EP the lights, EQ the flys,
   ER/ES the Beetlejuice bands, ET the set movers — and every one of them
   writes through `artnetTick` below, which is the only place in the frame
   where an Art-Net byte may touch anything.

   THREE THINGS THAT LOOK LIKE DETAILS AND ARE NOT:

   1. `ART.on === false` MUST LEAVE THIS GAME BEHAVIOURALLY IDENTICAL.  The
      switch is off on every boot and there is no socket, no listener and no
      per-frame cost until somebody throws it.

   2. THE SOCKET OPENS ON THE SWITCH, NOT ON LOAD.  A page served from GitHub
      Pages is HTTPS, and a LAN `ws://` from an HTTPS page is mixed content —
      so a connection attempt at boot would put a failure in the console of
      every player who has never heard of Art-Net.  It also would not work.
      Art-Net comes off the relay, same origin, or it does not come.

   3. NO `setTimeout`, ANYWHERE, INCLUDING THE RECONNECT.  Game timing comes
      off the frame `dt` (CLAUDE.md, and it is a hard rule).  The backoff is
      a number of seconds counted down in `artnetTick`.
   ========================================================================== */

/* RULING EU — how long a rig waits before it calls the desk gone.  A real rig
   does not snap to black when a laptop hiccups: at ART_STALE the LOOK is
   still exactly where the desk left it, and all that changes is who is
   allowed to write it (RULING EV). */
const ART_STALE = 2.0;
/* RULING EU — 1s, 2s, 4s, then 8s for ever.  Seconds, counted off `dt`. */
const ART_BACKOFF = [1, 2, 4, 8];
/* how long a socket may sit in CONNECTING before we give up on it */
const ART_CONNECT_MAX = 10;
/* HOW MUCH WIRE PROVES A WIRE.  A desk sends ~44 frames a second, so this is
   about a second of real traffic.  Forgiving the backoff on the handshake
   turned a flapping link into a 1Hz reconnect storm — and forgiving it on the
   FIRST frame only moved the storm one frame later, since a flap that carries
   23ms of traffic carries a frame.  A link has to hold up to be believed. */
const ART_PROVE = 44;

/* ============================================================================
   THE CHANNEL MAP (RULING EO)

   Universe 0, one universe, 512 channels:

     1 .. 273    the fixtures, patch order, SEVEN each:
                 intensity, red, green, blue, gobo, pan, tilt
     274 .. 301  the linesets, two each: target, speed        (RULING EQ)
     302 .. 306  house, work, lobby, backstage, practicals
     307         BEETLEJUICE house selector                   (RULING ER)
     308         BEETLEJUICE sign position                    (RULING ES)
     309         traveler open
     310 ..      the loaded show's set movers                 (RULING ET)

   EVERY BASE IS COMPUTED, NEVER WRITTEN DOWN.  The rig is 39 channels on
   every stage today and the fly rail is 14 lines, which is where 274 and 302
   come from — but a rig that grew by one lantern would silently repoint every
   channel after it if these were literals, and `docs/ARTNET.md` is generated
   off these same functions so the map cannot drift from the code.

   They are FUNCTIONS rather than constants because FIXTURES and FLY are
   filled by p4 and p3 at load and swapped wholesale by the stage walk; a
   const evaluated as this part loads would be measuring whatever existed at
   that instant.
   ========================================================================== */
const ART_CH_FIX = 7;                 // channels per fixture, uniform
/* a uniform footprint so QLC+ needs exactly ONE generic fixture definition.
   Pan and tilt are ignored on anything that cannot move (channels 23, 24 and
   34-39 are the movers today) — the bytes are still THERE, because a desk
   patching 39 identical 7-channel heads is what makes this workable by hand. */
function artFixBase(){ return 1; }
function artFlyBase(){ return artFixBase() + ART_CH_FIX * FIXTURES.length; }
function artHouseBase(){ return artFlyBase() + 2 * FLY.length; }
function artSelBase(){ return artHouseBase() + 5; }     // 307 selector, 308 sign, 309 traveler
function artMoverBase(){ return artSelBase() + 3; }

/* A MOVER'S TRAVEL.  Nothing in the rig declares its own range, so this is
   the range every head gets, and the map probe prints it per fixture rather
   than leaving it to be read out of here.

   PAN is symmetric: plus or minus 170 degrees about the plotted centre.

   TILT IS NOT, AND A SYMMETRIC ONE WASTED HALF THE CHANNEL.  `updateRig`
   poses a head as `rotation.x = (tilt + 90) * DEG` (p4), so tilt −90 is
   horizontal, 0 is straight down, and anything positive folds the head over
   backwards — while the rig's own plotted rest tilts are −45, −55 and −64.
   A range of ±135 therefore made bytes ~129 upwards unusable and put "tilt at
   50%" straight down, which is not what any operator means by the middle of a
   fader.  −180..0 is the real sweep: byte 0 straight up, 128 horizontal, 255
   straight down, and every byte in between lands somewhere a head can go. */
const ART_PAN = 170;
const ART_TILT_LO = -180;
const ART_TILT_HI = 0;

const ART = {
  on:     false,   // the switch (RULING EM).  Off on every boot, by ruling.
  ws:     null,    // the socket, while there is one
  buf:    null,    // the LATEST frame's bytes, or null.  One frame per tick:
                   // a desk running at 44Hz outruns a 90Hz eye's own rig
                   // updates on a bad frame, and the newest look is the only
                   // one worth drawing.
  live:   false,   // RULING EV — a frame inside ART_STALE.  THIS IS THE GATE.
  seen:   0,       // seconds since the last frame landed
  frames: 0,       // frames taken since the switch went on (the row prints it)
  step:   0,       // which backoff we are on
  retry:  0,       // seconds until the next attempt, 0 = not waiting
  opening:0,       // seconds this socket has spent in CONNECTING
  got:    0,       // frames out of THIS socket — what proves the wire
  bad:    0,       // frames that were not 512 bytes; the row prints it
  bandSc:   null,  // the SCENE the dressing memory belongs to (identity, not name)
  bandSign: null,  // and the sign record it belongs to
  houseBand: -1,   // RULING ER — the dressing band last APPLIED, not last seen
  signBand:  -1,   // RULING ES
  took:   false    // the handover has been done for this spell of driving
};

/* Same origin, always.  The relay serves the game, so the game's own origin
   IS the relay — which is what makes this work in a headset over `adb
   reverse` with no certificate anywhere.

   A page with no origin (jsdom's about:blank, and every suite in this repo)
   has nothing to connect to and gets null, so `artOpen` is a silent no-op
   there rather than a stack of failed connections in the test output.

   `loc` is there so the scheme choice can be asserted from a suite, which
   otherwise could only ever see the one origin jsdom gives it. */
function artUrl(loc){
  const l = loc || (typeof location !== 'undefined' ? location : null);
  if(!l || !l.host) return null;
  return (l.protocol === 'https:' ? 'wss://' : 'ws://') + l.host + '/artnet';
}

/* Returns the socket, or null if one could not be made.  IT NEVER ARMS THE
   BACKOFF ITSELF — every caller already asks `if(!ART.ws) artBackoff()`, and
   a version that also backed off inside the catch advanced the ladder TWICE
   per failure: 2, 8, 8, 8 instead of 1, 2, 4, 8.  A throwing constructor is
   not exotic — a blocked port, a malformed host and a mixed-content refusal
   all throw — so the doubling was reachable from a browser and invisible to
   a suite that only exercised the no-origin path. */
function artOpen(){
  if(ART.ws) return null;
  const url = artUrl();
  if(!url || typeof WebSocket !== 'function') return null;
  ART.retry = 0;
  let ws;
  try{ ws = new WebSocket(url); }
  catch(e){ return null; }
  ws.binaryType = 'arraybuffer';
  ART.ws = ws;
  ART.opening = 0;
  ART.got = 0;
  /* A CONNECTION IS NOT A CONNECTION UNTIL A FRAME COMES OUT OF IT, so the
     backoff is NOT forgiven here.  A relay restarting under a watcher, a
     proxy that accepts then resets, a headset whose wifi flaps — all of them
     complete the handshake and drop it, and forgiving the ladder on `onopen`
     turned that into a permanent 1Hz reconnect storm, which is the exact
     hammering the backoff exists to prevent.  The first real FRAME is what
     proves the wire, and that is where the step resets (artnetTick). */
  ws.onopen = ()=>{};
  /* THE ONLY THING onmessage DOES IS PUT THE BYTES DOWN.  Applying them here
     would write the rig from an event, mid-frame, between an update and the
     render that reads it — so the frame loop picks them up instead, once,
     in one place (RULING EU). */
  ws.onmessage = ev=>{
    if(typeof ev.data === 'string') return;   // the relay only ever sends binary
    ART.buf = new Uint8Array(ev.data);
  };
  ws.onerror = ()=>{};                        // onclose follows; nothing to add
  ws.onclose = ()=>{ ART.ws = null; if(ART.on) artBackoff(); };
  return ws;
}

function artBackoff(){
  ART.retry = ART_BACKOFF[Math.min(ART.step, ART_BACKOFF.length - 1)];
  ART.step++;
}

function artClose(){
  const ws = ART.ws;
  ART.ws = null;
  if(ws){ ws.onopen = ws.onmessage = ws.onerror = ws.onclose = null;
          try{ ws.close(); }catch(e){} }
}

/* THE SWITCH (RULING EM).  Both surfaces call this one function — the LIGHTING
   panel's row and the VR console's — because a control that exists on one
   surface and not the other is two different controls wearing one name. */
function artSetOn(on){
  on = !!on;
  if(on === ART.on) return ART.on;
  ART.on = on;
  if(on){
    ART.step = 0; ART.retry = 0; ART.frames = 0; ART.took = false;
    ART.houseBand = -1; ART.signBand = -1;      // the bands say themselves again
    ART.seen = ART_STALE + 1; ART.live = false; ART.buf = null;
    artOpen();
    if(!ART.ws) artBackoff();      // nothing to connect to yet: try again shortly
  } else {
    /* SWITCH-OFF: NOTHING SNAPS (RULING EM).  The rig holds its last Art-Net
       look and the board resumes writing from there — which is exactly what
       happens when an operator takes a rig back off a remote desk. */
    ART.live = false; ART.buf = null; ART.retry = 0; ART.step = 0; ART.took = false;
    artClose();
  }
  if(typeof artSyncRow === 'function') artSyncRow();
  return ART.on;
}

/* RULING EV — THE GATE THE REST OF THE GAME ASKS.  Not "is the switch on" but
   "is a desk actually talking": the switch alone must never take the board
   away, because switching it on with no relay running is the first thing
   anybody will do, and a board that went dead would be indistinguishable
   from a broken game. */
function artDriving(){ return ART.on && ART.live; }

/* THE HANDOVER (RULINGS EM and EV together).  EM says a cue fade caught
   mid-flight halts where it is INSTEAD OF FIGHTING THE DESK; EV says throwing
   the switch with no desk connected changes NOTHING.  Both are satisfied by
   asking when, rather than which: the halt belongs to the moment a desk
   actually starts driving, not to the moment somebody presses a button.
   Running it on the switch froze a five-second cue fade at 10% for an
   operator who had no relay running at all, which is precisely the
   indistinguishable-from-broken that EV exists to prevent.

   AND IT IS THE PALACE'S FADES, NEVER ANOTHER STAGE'S (RULING EN).  FIXTURES
   is swapped wholesale by the stage walk (p2k), so a sweep taken from the Arc
   halted the ARC's fades and left the Palace's running — the one rig it was
   for.  `took` is per handover rather than per switch, so walking INTO the
   Palace while a desk is already talking still gets the halt. */
function artHandover(){
  const driving = artDriving() && (typeof STAGE === 'undefined' || STAGE === 'palace');
  if(!driving){ ART.took = false; return false; }
  if(ART.took) return false;
  ART.took = true;
  for(const f of FIXTURES){ f.lvlDur = 0; f.colDur = 0; }
  /* AND THE BANDED CHANNELS ARE RE-ASSERTED (RULINGS ER, ES).  Every light
     channel says itself again every frame; the two band channels speak only
     on a CHANGE, so without this a desk that stuttered — which RULING EV says
     WILL happen, and hands the board back when it does — came back to find a
     cue had redressed the house, and never corrected it, because the fader
     had not moved across a boundary.  The fader and the stage then disagreed
     for the rest of the show with nothing anywhere to say why. */
  ART.houseBand = -1; ART.signBand = -1;
  return true;
}

/* ============================================================================
   RULING EP — THE LIGHTS ARE RAW WRITES, AND THE FADE ENGINE NEVER FIGHTS

   A desk fades by SENDING A VALUE EVERY FRAME.  Stacking the game's own fade
   engine on top of that would make every fade mushy — the desk would ask for
   0.4 and the rig would set off towards it over half a second, arriving just
   as the desk asked for 0.45.  So every write here sets `lvlDur`/`colDur` to
   zero: `updateFades` (p6) only engages while a duration is pending, so the
   desk's own fades stream straight through untouched.

   The desk fades.  The game obeys.
   ========================================================================== */
function artLights(b){
  const nGobo = (typeof GOBOS !== 'undefined' && GOBOS.length) ? GOBOS.length : 6;
  const base = artFixBase() - 1;                 // to a 0-based index into the frame
  for(let i = 0; i < FIXTURES.length; i++){
    const o = base + i * ART_CH_FIX;
    if(o + ART_CH_FIX > b.length) break;         // a rig wider than one universe
    const f = FIXTURES[i];
    f.level = b[o] / 255;
    f.lvlDur = 0;
    f.color.setRGB(b[o + 1] / 255, b[o + 2] / 255, b[o + 3] / 255);
    f.colDur = 0;
    /* byte / 43 lands 0..255 on the six gobos, with the top slot getting the
       ragged end (255/43 = 5.9).  Clamped rather than trusted, because a
       seventh gobo would otherwise be a black texture and no error. */
    f.gobo = Math.min(nGobo - 1, Math.floor(b[o + 4] / 43));
    /* movers only: a fixed lantern's pan and tilt bytes are ignored, and its
       `aim` is left exactly where the plot put it */
    if(f.mover){
      f.panT  = (b[o + 5] / 127.5 - 1) * ART_PAN;
      f.tiltT = ART_TILT_LO + (b[o + 6] / 255) * (ART_TILT_HI - ART_TILT_LO);
    }
  }
  /* The house circuits.  `syncMasters` is NOT called here — writing four DOM
     values 44 times a second for a board nobody may be looking at is not what
     this is for.  The SECTION faders recover on their own (refreshChannelStrip
     -> syncSections reads HOUSE at 10Hz, p7); the `#hl`/`#wl` master sliders
     do NOT, because syncMasters is not on that path, so they read stale while
     a desk drives the house.  That is a row for the ARTNET UI to solve, not a
     reason to repaint the DOM at packet rate. */
  const h = artHouseBase() - 1;
  if(h + 4 < b.length){
    HOUSE.house     = b[h]     / 255;
    HOUSE.work      = b[h + 1] / 255;
    HOUSE.lobby     = b[h + 2] / 255;
    HOUSE.backstage = b[h + 3] / 255;
    HOUSE.practical = b[h + 4] / 255;
  }
}

/* ============================================================================
   RULING EQ — THE FLYS MOVE THROUGH THEIR OWN MOTOR, AND NEVER TELEPORT

   Two channels a line, in FLY order: target, then speed.

   TARGET is the whole travel: byte 0 is the lowest this line may come — which
   is `minTrimOf`, where its goods kiss the deck, NOT the floor — and 255 is
   the grid.  It is applied through `flyTo`, which works the lock itself and
   clamps, so A DESK CANNOT DRIVE A CLOTH THROUGH THE STAGE any more than a
   cue can.  That is an INVARIANT, and routing through flyTo is how this round
   inherits it rather than reimplementing it.

   SPEED, and byte 0 is PARKED.  A dead universe — a desk switched off, a
   patch that never reached these channels, a relay sending zeros — moves no
   scenery.  A line whose speed byte is 0 does not move whatever its target
   says, which is also what stops a line that was already travelling.
   ========================================================================== */
const ART_FLY_MAX = 2.0;             // metres a second at byte 255

function artFlys(b){
  const base = artFlyBase() - 1;
  for(let i = 0; i < FLY.length; i++){
    const o = base + i * 2;
    if(o + 1 >= b.length) break;
    const ls = FLY[i];
    const byte = b[o + 1];
    ls.artSpeed = (byte / 255) * ART_FLY_MAX;
    /* PARKED.  Not "moves very slowly", and not merely "held still by a zero
       speed" either: the line is STOPPED WHERE IT STANDS.

       Leaving the target alone looked right and was not.  A line caught
       mid-travel then kept its old target while its position stopped, and
       updateFly reads a target it is not at as a move in progress — so
       `ls.moving` never cleared, `Snd.railStop` never ran, and the rail motor
       loop played for the rest of the session on a line that had not moved
       for ten minutes.  The likeliest first use finds this: a desk patched
       only for the 273 light channels sends zeros on 274-301, so every line
       is parked from the moment the switch goes on.

       Writing pos into target is what a stop IS, and it leaves the runaway
       physics alone: the runaway clear needs target and pos to DIFFER. */
    if(!byte){ ls.target = ls.pos; continue; }
    const lo = minTrimOf(ls);
    flyTo(ls, lo + (b[o] / 255) * (OUT_TRIM - lo));
  }
  /* THE TRAVELER, one channel: 0 shut, 255 open.  It belongs to whichever
     line is carrying goods that declare themselves a traveler, and the map
     probe prints which line that is rather than leaving it to be counted off
     this comment.

     AND IT IS NOT THE SAME LINE IN EVERY SHOW, which is what this comment
     used to get wrong: it said "the house curtain today", and that is only
     true of the Palace's STANDING HANG, where the traveler is line 2.  Load
     Beetlejuice and it is LINE 1 — the show hangs its own `bjCurtain`, which
     also declares `traveler`, and `findIndex` takes the first; the Palace
     house curtain is not on the rail at all.  docs/ARTNET.md measures and
     prints both hangs, because an operator patching 309 needs to know its
     target line moves with the production.

     AND IT IS PARKED BY ITS OWN LINE'S SPEED BYTE.  Written unconditionally,
     this was the one piece of scenery a dead universe DID move: the instant
     the switch went on with nothing patched to 309, the house curtain ran
     itself shut at 0.42 of its full draw a second — about 2.4 seconds end to
     end, and `ls.open` is a FRACTION, never metres — in front of the
     audience.  docs/ARTNET.md measures it.  RULING EQ's principle is
     that a dead universe moves no scenery, and a curtain is scenery; EO's
     table says 0 is shut, and it still is, once somebody is actually driving
     that line.  The traveler hangs on a lineset, so the lineset's own speed
     byte is what says whether the desk is driving it. */
  const t = artSelBase() + 1;                    // channel 309, 0-based
  if(t < b.length){
    const i = FLY.findIndex(ls=>ls.goods && GOODS[ls.goodsKey] && GOODS[ls.goodsKey].traveler);
    const so = artFlyBase() - 1 + i * 2 + 1;     // that line's speed byte
    if(i >= 0 && so < b.length && b[so]) FLY[i].travTarget = b[t] / 255;
  }
}

/* ============================================================================
   RULINGS ET AND EX — THE SET MOVERS, ONE TARGET CHANNEL EACH, AT THEIR OWN
   SPEED, AND PARKED UNLESS SOMETHING IS REALLY DRIVING THEM

   From artMoverBase(), SHOW.scenes in DECLARATION ORDER, and inside a scene
   its whole-group travel `sc.mv` FIRST and then its part movers `sc.pmv` in
   the order they were declared.  One channel each and no speed channel —
   Jack asked for speed on the flys only.

   RULING EX — BYTE 0 IS NOT A POSITION, IT IS THE ABSENCE OF A COMMAND.  ET
   as first written made byte 0 mean `home`, and the consequence was measured
   before it landed: a desk patched only for the 273 light channels sends
   zeros on everything else, so 512 zeros commanded EVERY mover in the loaded
   show home — on Beetlejuice that walks the parked attic 19.50m onto the deck
   while it is drawn and flies the exterior cloth in.  RULING EQ's stated
   principle is that a dead universe moves no scenery, and a set is scenery.
   Jack ruled it PARKED UNLESS DRIVEN: 0 is no command and the mover stays
   wherever the show left it, 1..255 spans home..out.  Byte 1 IS home, exactly
   — the cost is one lost code point, 254 steps across the travel instead of
   255 — and it puts the movers on the same footing as the flys (EQ) and the
   house curtain on channel 309: on all three, a zero is a channel nobody is
   driving.  What that then MEANS is NOT the same on all three, and the
   difference is written out at artMoverSet.

   THE RANGE IS READ OFF THE RECORD WHEREVER THE RECORD HAS IT.  Byte 1 is
   `m.home`.  Byte 255 is `m.out` WHEN THE RECORD DECLARES A NUMERIC ONE —
   every part mover does, because sceneTravelPart fills the field in whether
   the caller passed it or not, and no whole-group travel ever does, because
   sceneTravel has no `out` parameter at all.

   AND FOR THOSE THE 0 IS A FALLBACK THIS CODE CHOOSES, NOT SOMETHING THE
   RECORD SAYS — worth being honest about, because the two cases it covers are
   not alike.  On the interior wagon 0 is genuinely its acting offset and the
   fallback lands on the right number by agreeing with the cue.  On the
   exterior house 0 is also its HOME, which is what makes that channel one-way
   (below).  Nothing in the code tells them apart.  `sc.parkMv` and
   `sc.parkMvAt` are SCENE fields rather than mover fields and are not
   consulted — the plan's correction #2.

   AND THE BYTE→METRE MAPPING IS NOT FIXED FOR THE SESSION.  `bjWingPack`
   rewrites `out` on the attic, bedroom and closet whenever one of Jack's
   model files lands, so six of the twelve channels change meaning under a
   desk holding a steady byte.  That is the ruling working, not failing — the
   range is the record's — but its own re-seat (`m.off = m.target = m.out`) is
   undone by this block on the next frame, so a set that grew while a desk was
   driving lands where the DESK says rather than where the pack put it.

   A SCENE THE RAIL HAULS IS NOT ON THIS MAP AT ALL (RULINGS CW, ES).  A show
   may declare hauls that are not linesets — SHOW.flyExtras, the Beetlejuice
   sign being the one there is — and RULING ES gives that sign its own banded
   channel, 308, written on a band CHANGE only.  This block writes EVERY
   FRAME, and a per-frame write outvotes a change-only one absolutely: 308
   would put the sign on its stop and the next packet would haul it back, so
   the channel would be dead on arrival and nothing would say why.  So every
   scene named by a flyExtra is skipped here, travel and parts alike, and the
   rail keeps what the rail hauls.  It costs Beetlejuice one channel: the
   block is 310..321, twelve movers, and the sign is addressed on 308.

   ONLY THE TRAVEL MOVER CAN ACTUALLY COLLIDE — flyExtraTo and flyExtraToStop
   write `sc.mv` and nothing else (flyExtraMover only READS it) — so skipping
   the parts as well is the wider rule of the two.  It is the right one while
   it costs nothing (bjSign's scene has `pmv === null`, and it is the only
   haul in the game) because it keeps ONE owner for a hauled scene rather than
   splitting it across two surfaces; if one ever grows parts they will need a
   ruling rather than a silent channel.

   AND THE SAME GOES FOR A SECOND HAUL, WHICH WOULD BE UNREACHABLE FROM THE
   DESK ENTIRELY.  This exclusion is on `x.scene`, so ANY haul takes its scene
   off the map — but RULING ES serves only `key === 'bjSign'`, so a show that
   declared a second one would get no mover channel AND no band channel, and
   nothing would say why.  Also a ruling, not a silent channel.

   WHICH LEAVES ONE CHANNEL THAT IS ONE-WAY, AND IT IS NOT A BUG IN THIS
   FUNCTION.  A whole-group travel that declares `home` 0 and no `out` has
   `home` and `out` both 0, so every byte from 1 to 255 commands it to exactly
   where byte 1 does.  IT IS NOT INERT, and calling it that would be the more
   dangerous mistake: Beetlejuice's `house` travel is such a mover, and the
   Maitlands house spends most of the show flown OUT — so any byte at all
   walks it home, and no byte can send it back.  The desk can fly that house
   IN and can never fly it OUT — and it hangs a 12.6m drop dead centre of a
   15m opening, over whatever is playing.  docs/ARTNET.md prints the range as
   0.00..0.00 rather than hiding it, because an operator who patches that
   fader deserves to know it only works one way; until `tools/artnet-map.js`
   generates that file THIS COMMENT is the only place it is written down.

   Under ET as first written it was worse than one-way: it wrote 0 every frame
   a dead universe was connected, so the set could never fly out AT ALL.
   RULING EX is what defuses that half — the channel now does nothing until
   somebody drives it, and then it commands home, which is what its own record
   says.  Widening the range would mean consulting `sc.parkMv`, which the
   plan's correction #2 forbids; if it is to be widened it wants a ruling.

   THE WRITE IS `m.target` AND NOTHING ELSE.  `m.off` and the group's own
   position belong to sceneMvAdvance, which walks the record at `m.speed` on
   the scene tick that already exists — so a desk move looks exactly like a
   cue move, and no desk can put a house across the stage between two frames.
   Same reason as RULING EQ, and the same machinery.

   THE BLOCK IS DERIVED EVERY FRAME, so a show change re-bases it for free:
   showStrike empties SHOW.scenes and the next show builds new records, and a
   list cached at first use would go on writing into a struck show's movers
   for ever while the loaded one stood still.

   AND WHAT 512 ZEROS DO, SAID OUT LOUD RATHER THAN LEFT TO BE FOUND: under
   EX, nothing whatever.  Every mover keeps the target the show gave it, the
   parked sets stay parked, and a desk that has never been patched past the
   273 light channels cannot touch a single piece of scenery — which is the
   likeliest first real use, and is what EQ said all along.
   ========================================================================== */

/* the far end of the travel: what the record declares, or 0 on its own axis.

   `Number.isFinite`, NOT `typeof`, and that is the one guard that catches the
   value that matters: `typeof NaN` is 'number'.  A NaN target makes
   sceneMvAdvance take its step branch every single frame — `Math.abs(NaN) <=
   step` is false — so the set walks off in +axis at its own speed and NEVER
   ARRIVES, with no error anywhere.  Unreachable today (sceneTravel coerces
   `home` with `|| 0` and sceneTravelPart fills `out` in), and the safe form
   costs exactly the same. */
function artMoverOut(m){ return Number.isFinite(m.out) ? m.out : 0; }
function artMoverSet(m, byte){
  /* RULING EX.  0 is NOT a position — it is the absence of a command, and the
     mover is left exactly as the show left it.  Unlike a fly line there is
     nothing to stop: sceneMvAdvance walks `off` towards `target` and a mover
     caught mid-travel simply finishes the move the show asked for, which is
     what "the desk is not driving this" should look like. */
  if(!byte) return;
  if(!Number.isFinite(m.home)) return;            // same reason, the near end
  const out = artMoverOut(m);
  /* target ONLY.  Writing `off` here would be the teleport RULING ET forbids,
     and writing the group's position would be worse than useless — the set is
     frozen (lockShowStatic) and only sceneMvAdvance's own write goes through
     a mover's live matrix.

     1..255, not 0..255: byte 1 is home and byte 255 is out. */
  m.target = m.home + ((byte - 1) / 254) * (out - m.home);
}
/* is this scene hauled by the rail as a fly extra?  Then it is ES's, not
   ours — and it is asked of SHOW.flyExtras at the moment of the frame, never
   cached, because the list is the loaded show's and shows change. */
function artMoverHauled(sc){
  const xs = SHOW.flyExtras;
  if(!xs || !xs.length) return false;
  for(const x of xs) if(x && x.scene === sc.name) return true;
  return false;
}
function artMovers(b){
  if(!SHOW.scenes || !SHOW.scenes.length) return;
  let o = artMoverBase() - 1;                     // to a 0-based index
  for(const sc of SHOW.scenes){
    if(artMoverHauled(sc)) continue;              // the rail has it (CW, ES)
    /* a rig plus a rail plus a show with a lot of scenery could run past 512;
       the channels that fit are driven and the rest are simply not there */
    if(sc.mv){ if(o >= b.length) return; artMoverSet(sc.mv, b[o++]); }
    /* `for..in` is INSERTION order here, which is the declaration order the
       ruling asks for — but only because every part mover is named.  A key
       that looks like an array index ('0', '2') would be hoisted to the front
       of the walk and would silently repoint every channel after it.  Same
       family as the computed bases: name your part movers. */
    if(sc.pmv) for(const k in sc.pmv){ if(o >= b.length) return; artMoverSet(sc.pmv[k], b[o++]); }
  }
}

/* ============================================================================
   RULINGS ER AND ES — TWO BANDED CHANNELS, HIS SPLITS EXACTLY

   Jack, in the brief: "make it so for beetljuice it has a channel and if it is
   between 0 and 85 it is the maitlands house. if it between 86 and 170 it is
   the deetz house and if it is between 171 and 255 it is the beetlejuice
   house."  Channel 307 is that channel.  Channel 308 is the sign, on the same
   three splits, driving its own named stops (RULING DH).

   BAND CHANGE ONLY, AND THAT IS NOT AN OPTIMISATION.  `bjRedress` detaches and
   re-attaches whole scene-graph nodes — RULING CN holds two complete houses
   out of the world so only one exists at a time — and running that 44 times a
   second would rebuild the graph on every packet.  `flyExtraToStop` retargets
   a mover, and re-commanding it every frame would restart the haul.

   NEITHER CHANNEL DOES ANYTHING TO A SHOW THAT HAS NO SUCH SCENERY.  The
   band is not even remembered in that case, so loading Beetlejuice with the
   fader already sitting at 200 still redresses on the first frame after.
   ========================================================================== */
const ART_HOUSES = ['maitland', 'deetz', 'bj'];
function artBandOf(byte){ return byte <= 85 ? 0 : (byte <= 170 ? 1 : 2); }

function artBands(b){
  const sel = artSelBase() - 1;                 // channel 307, 0-based
  if(sel + 1 >= b.length) return;

  /* THE MEMORY BELONGS TO THE SCENERY, NOT TO THE SHOW.  Keying it on the
     production name looked equivalent and was not: loading Beetlejuice a
     SECOND time builds fresh scene objects dressed the default way, and the
     name has not changed — so the band would still read as applied and the
     fresh house would sit there wearing the wrong dressing until somebody
     happened to move the fader.  Object identity changes on every load, so
     it is the identity that is remembered. */

  /* RULING ER — the three dressings, through the show's own mechanism */
  const sc = SHOW.scenes && SHOW.scenes.find(s=>s.dress &&
    ART_HOUSES.every(k=>s.dress[k]));
  if(sc){
    if(sc !== ART.bandSc){ ART.bandSc = sc; ART.houseBand = -1; }
    const hb = artBandOf(b[sel]);
    if(hb !== ART.houseBand){
      ART.houseBand = hb;
      sc.dressOn = ART_HOUSES[hb];
      bjRedress(sc);
      /* AND A CUE'S DEFERRED DRESS IS NOT STILL OWED.  RULING AY holds a
         dress until the set is out of sight, and a cue that armed one before
         the desk took over would fire it at the next changeover — silently
         overwriting the desk's most recent word with an older one.  The band
         is the newer instruction; the pending one is spent. */
      if(SHOW.pendDress && sceneFind(SHOW.pendDress.scene) === sc) SHOW.pendDress = null;
    }
  } else if(ART.bandSc){
    /* NOTHING TO DRESS ANY MORE.  Without this the reference outlives the
       production: showStrike disposes the scenery and empties SHOW.offstage,
       and a held dressing group keeps its meshes and their attribute arrays
       alive for the rest of the session. */
    ART.bandSc = null; ART.houseBand = -1;
  }

  /* RULING ES — the sign, the same idiom and the same splits: 0-85 FLOOR,
     86-170 PRE-SHOW, 171-255 UP, which are the stops the show declares */
  const x = SHOW.flyExtras && SHOW.flyExtras.find(e=>e.key === 'bjSign');
  const st = x && flyExtraStops(x);
  const sb = artBandOf(b[sel + 1]);
  /* `sb < st.length` says what is meant.  Comparing the STOP COUNT against
     the number of houses was a coincidental coupling: a fourth house dressing
     would have silently switched channel 308 off. */
  if(st && sb < st.length){
    if(x !== ART.bandSign){ ART.bandSign = x; ART.signBand = -1; }
    if(sb !== ART.signBand){
      ART.signBand = sb;
      flyExtraToStop(x, sb);
    }
  } else if(ART.bandSign && !st){
    ART.bandSign = null; ART.signBand = -1;
  }
}

/* ONE WRITER, ONE PLACE IN THE FRAME (RULING EU).  Called from p7's tick,
   once, after input and before every system that reads the rig. */
function artnetTick(dt){
  if(!ART.on){ ART.buf = null; return; }

  ART.seen += dt;
  if(ART.seen > ART_STALE){ ART.live = false; ART.took = false; }

  /* the reconnect, counted in seconds off the frame — never a timer */
  if(!ART.ws && ART.retry > 0){
    ART.retry -= dt;
    if(ART.retry <= 0){ artOpen(); if(!ART.ws) artBackoff(); }
  }
  /* A SOCKET STUCK IN CONNECTING IS NOT A SOCKET, AND IT STALLS THE LADDER —
     `ART.ws` is truthy the instant the constructor returns, so the retry
     branch above never runs while a connection hangs.  A blackholed relay
     (a host that drops rather than refuses) would otherwise wait on the
     browser's own TCP timeout, which is over a minute, and longer on a
     headset.  Give up on it and rejoin the ladder. */
  else if(ART.ws && ART.ws.readyState === 0){
    ART.opening += dt;
    if(ART.opening > ART_CONNECT_MAX){ artClose(); artBackoff(); }
  }

  /* THE LATEST FRAME WINS AND THE REST ARE DROPPED.  Taking the buffer is not
     a formality: its ARRIVAL is the whole of the live/stale reading that
     RULING EV gates on and that both ARTNET rows print.  What the 512 bytes
     MEAN arrives with RULING EP, and lands right here — this is the one place
     in the frame where an Art-Net byte may touch the rig. */
  const b = ART.buf;
  ART.buf = null;
  if(!b) return;
  /* The relay pads and truncates to exactly 512 (RULING EL), so anything else
     did not come from it and has no channel numbering we can trust.

     COUNTED, NOT MERELY DROPPED.  The mismatch this really catches is not a
     relay of the wrong vintage — the relay serves the game, so the two cannot
     disagree — it is a client-side fault like a socket left on its default
     binaryType, where every frame arrives as an empty view and a silent drop
     would read as connected-but-stale with nothing anywhere to say why. */
  if(b.length !== 512){ ART.bad++; return; }

  ART.frames++;
  ART.got++;
  ART.seen = 0;
  ART.live = true;
  /* A WIRE THAT HELD UP IS WHAT FORGIVES THE LADDER — not a handshake, and
     not one frame either: a flap that carries 23ms of traffic carries a
     frame, so forgiving on the first one just moves the storm one frame
     later.  See ART_PROVE. */
  if(ART.got >= ART_PROVE) ART.step = 0;
  artHandover();

  /* RULING EN — THE PALACE ONLY, EVER.  A packet is still RECEIVED on another
     stage, and everything above this line has already run, so the row keeps
     reading live and an operator can see the desk is talking.  It simply
     writes nothing.  No per-stage universes, and nothing is ever written into
     a parked stage's captured state — that machinery is not built, and this
     ruling says it never is without a new one.

     The test REQUIRES the Palace rather than exempting the undefined: a
     "never write unless" ruling should fail shut.  `STAGE` is unconditionally
     defined in p2k so this cannot bite today, but the safe polarity costs
     nothing. */
  if(typeof STAGE === 'undefined' || STAGE !== 'palace') return;

  artLights(b);
  artFlys(b);
  artMovers(b);
  artBands(b);
}

/* ============================================================================
   THE BOARD YIELDS, AND THE ROW THAT SAYS SO      RULINGS EM and EV together

   EVERY GATE IN THE GAME ASKS artDriving(), NEVER ART.on.  That is RULING EV
   in one line: the switch alone must never take the board away, because
   throwing it with no relay running is the first thing anybody will do, and a
   board that went dead would be indistinguishable from a broken game.  Switch
   on, no desk: every cue, sub, fader, fly and rope works exactly as it does
   today.

   WHAT IS NOT GATED, DELIBERATELY: RIG.grand and RIG.blackout still multiply
   the final output in updateRig.  The in-game grand outranks the desk the way
   a house console's grand outranks a remote one — it is the safety.
   ========================================================================== */

/* The one sentence the board says when it will not move, in the one place, so
   the four operator paths cannot drift apart on the wording.  Returns true
   when the caller should stand down.  Faders and submasters do NOT use it:
   they are dragged, and a toast per frame of a drag is not a message, it is
   noise — they simply ignore the write, and the row says why. */
function artYields(what){
  if(!artDriving()) return false;
  if(typeof toast === 'function') toast((what || 'board') + ' is on ART-NET');
  return true;
}

/* WHAT BOTH ROWS PRINT, FROM ONE FUNCTION.  live/stale is not decoration here:
   it IS the gate (RULING EV), so the row has to say which side of it we are on
   and how old the reading is.  `seen` is seconds since the last frame landed,
   aged in artnetTick off the frame dt. */
function artRowText(){
  if(!ART.on) return 'OFF — the board has it';
  if(!ART.frames) return 'ON — no desk yet, the board has it';
  return (ART.live ? 'LIVE' : 'STALE') + ' — ' + ART.seen.toFixed(1) +
         's since the last packet' + (ART.live ? '' : ', the board has it back');
}

/* THE DESK'S FACE OF THE ROW (the markup is p1's, on the LIGHTING page).  The
   headset's face is vrPageLighting (p9) and it presses the same artSetOn — a
   control that exists only in the DOM does not exist in VR. */
function artSyncRow(){
  const st = $('#artState'), b = $('#artOn');
  if(st) st.textContent = artRowText();
  if(b){ b.textContent = ART.on ? 'ON' : 'OFF'; b.classList.toggle('on', ART.on); }
}
if($('#artOn')) $('#artOn').onclick = ()=>{ artSetOn(!ART.on); };
artSyncRow();
