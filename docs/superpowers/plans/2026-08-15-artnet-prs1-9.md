## Two corrections to the spec, before any code

1. **`src/p6c.txt` is taken.** It is the carpenters (ARCHITECTURE.md). The
   spec's "new part `src/p6c.txt`" is a naming slip; the substance ("a new
   part after `p6b`") is unaffected. The part is **`src/p6d.txt`**, placed
   immediately after `p6c` in `build.sh` — still before `p5c`, still calling
   p3/p5c/p6 functions at runtime only. Every "p6c" in the spec means p6d.
2. **RULING ET's `m.out`, read literally.** `sc.mv` (a scene's travel mover,
   p5c:471) has no `out` field; only part movers (`sc.pmv[k]`, p5c:487) carry
   one, and it is what parks them AND what they travel to — which is exactly
   the spec's parenthetical "(parks and part travels)". So the rule is:
   **`m.out` when the mover record declares a numeric one, else 0 on its
   axis.** `sc.parkMv`/`parkMvAt` are scene fields, not mover fields, and are
   not consulted. The map probe prints every mover's real metre range, so the
   polarity is read off the code rather than off this paragraph.

## The standing gate

**`ART.on === false` must leave the built file behaviourally identical.**
Every PR in this chain holds that, and every PR is green before and after.

## Per-PR discipline (house rules, no exceptions)

- Failing-test-first; **every new assertion negative-checked by sha** —
  mutation proved present in the BUILT file AND proved to have changed it,
  restore proved byte-identical. Rebuild in the restore step, not just the
  mutate step.
- Suites green before AND after. `node probe-lint.js` after any probe edit.
- Two-stage review (spec compliance, then quality) before push.
- Post-merge: `main` rebuilds byte-identical, 21/21 on the merged result,
  branch deleted local and remote.
- Commits `-F` a message file (PowerShell 5.1). Never `git add -A`.
- PRs via the GitHub API with the stored credential; JSON body written to the
  scratchpad, never inlined.
